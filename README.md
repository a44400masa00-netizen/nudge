# Nudge

3つのアプリを1つに合体させたものです。

1. 勉強コーチ（元のアイデア）: カレンダー・位置情報・スマホの使用状況から状況を推測し、他のアプリを見ていても画面上部にAIのメッセージをポップアップ表示して勉強を促す
2. しつこい通知（在宅学習）: 決めた時間帯に自宅にいると、対象アプリ（勉強アプリなど）を開くまで数分おきに通知でしつこく催促する
3. 音声アシスタント（デイリー機能）: 「ヘイ、デイリー」と呼びかけると起動する常駐の音声アシスタント。タイマー・アラーム・音楽再生・ライト・音量などをハンズフリーで操作できる

## アップデートできない（毎回アンインストールが必要）だった問題について

以前は、GitHub Actionsでビルドするたびに署名の鍵がランダムに作り直されていたため、Androidが「別のアプリへの更新」とみなしてインストールできませんでした。今は `keystore/debug.keystore` という固定の鍵をリポジトリに含め、常にこの鍵で署名するようにしたので、次回のビルドからは上書きインストールできるはずです。

この `keystore/debug.keystore` は、あくまで開発中の識別用の鍵で、Google Playなどには使えない簡易なものです。他の人に公開する予定がなければ、このままで問題ありません。

## GitHubでAPKを作る手順
1. GitHubのリポジトリの中身を、このzipの中身で置き換える（`.github`フォルダも含めて全部）
2. 「Actions」タブ →「Build APK」が自動で走る（走らなければ Run workflow）
3. 成功したら、実行結果ページ下の「Artifacts」から `app-debug-apk` をダウンロード→展開すると `app-debug.apk`
4. スマホにインストール
5. 失敗したら、赤い×の実行→失敗したステップのログ画面をスクリーンショット

## 初期設定の順番
1. ①の権限を、上から順に全部許可していく（マイクや通知へのアクセスなど、初回はダイアログが複数回出ます）
2. ②にGemini APIキーを入力（Google AI Studioで無料取得）
3. ③で自宅・学校・最寄り駅・塾の位置を地図で登録（在宅判定などにも使われる）
4. ④の動作を必要なら調整して保存
5. ⑤「見守りを開始」→④の声かけと⑥のしつこい通知がまとめて動き出す
6. 必要なら⑥でしつこい通知の対象アプリと時間帯を設定
7. 必要なら⑦で音声アシスタントの設定をして、有効にする

## この合体で変更した点（元の2つのアプリから）

- **在宅判定をひとつに統一しました。** 元の「しつこい通知」アプリはWi-FiのSSIDで自宅を判定していましたが、StudyNudge本体に既にある「自宅」の地図ピン（GPS）による判定に統一しました。Wi-Fiの登録は不要です。
- **通知の文面を少しやわらかくしました。** 元の文面には、放置が続いた時に強く突き放すような言い回しがありました。継続して頑張ってもらうという仕組み自体はそのまま活かしつつ、文面は「もう少し頑張りましょう」「今日はここまでにしましょう」といった、しつこいけれど厳しすぎない言い方に変えています。気に入らない場合は `app/src/main/java/com/example/studynudge/reminder/NotificationHelper.kt` の文言を書き換えてください。
- **「毎日◯時に開始チェック」専用のアラームを削除しました。** 見守り本体（NudgeService）が1分おきに全部まとめて確認する仕組みに乗せたので、別のアラームは不要になりました。むしろ元の15分おきより反応が早くなっています。
- **音声アシスタントは、Expo（React Native）で作られていたものを、Kotlinのネイティブ部分だけを取り出して移植しました。** 見た目の画面（React Native側）は使っておらず、常駐サービスが直接しゃべる・聞く形になっています。「ヘイ、デイリー」という呼びかけの言葉は、学習済みのモデルファイルに固定されているため、アプリ名を変えても変更できません（変えるには専用のモデルを作り直す必要があります）。

## ビルドが失敗しやすい箇所（優先度順）

1. **呼びかけ検出（ONNX Runtime）** ライブラリ自体は安定していますが、`melspectrogram.onnx` と `embedding_model.onnx` をビルド時にネットから取得しています（`hey_daily.onnx` は同梱済み）。取得に失敗した場合は、ビルドのログにエラーが出ます。
2. **権限まわり** 音声アシスタント・しつこい通知は、使う権限の数がかなり多いです（マイク、通知へのアクセス、正確なアラーム、使用状況など）。実機で動かないときは、まずアプリ画面の①のボタンを一通り押して許可されているか確認してください。

## 地図について

地図は国土地理院の無料タイル（日本国内向け・APIキー不要）を使っています。OpenStreetMapの無料サーバーはアプリからのアクセスをブロックすることがあるため、こちらを使っています。

## パソコンのローカルAI（Geminiの無料枠を節約したい場合）

`nudge-local-ai-relay.html` を、パソコンのブラウザ（Chrome）で開いたままにしておくと、そのパソコンのグラフィックボードでAIが動き、Firebase経由でスマホからの声かけ・音声アシスタントに応答します。

- アプリの「パソコンのローカルAI」カードに、FirebaseのデータベースURLと合言葉を入れ、「パソコン内のAIを使用する」を有効にすると、勉強の声かけと音声アシスタント（デイリー）の両方が、**まずパソコンに問い合わせ、繋がらなければ自動的にGeminiに切り替わります**
- パソコン側のページは、動いている間ずっと「生きています」の合図をFirebaseに書き込みます。**合図が古ければ（ページが閉じていれば）、スマホは待たずに、すぐGeminiに切り替えます**。そのため、アプリとページは**必ず新しい版の両方**を使ってください（古いページだと、合図が無いので、パソコンのAIは使われません）
- `nudge-local-ai-relay.html` は、claude.aiのリンクではなく、**ダウンロードしたファイルとして直接開く**必要があります（claude.ai経由だと、セキュリティ制限で外部への通信がブロックされます）
- 端末（スマホ本体）だけで動くAIは、このアプリでは使いません

### いちばん大事な設定: ChromeにRTX 3060を使わせる

お使いのパソコンはGPUが2枚（RTX 3060とIntel内蔵）あり、**何もしないと、ChromeはIntel内蔵のほうでAIを動かします**。そうなると、極端に遅く、パソコン全体も重くなります（実際にタスクマネージャーで、Intelが98%、RTX 3060が0%になっていました）。

1. Windowsの「設定 → システム → ディスプレイ → グラフィックス」を開く
2. 一覧から「Google Chrome」を選ぶ（なければ「参照」で chrome.exe を追加）
3. 「オプション」→「高パフォーマンス」（NVIDIA GeForce RTX 3060）→「保存」
4. Chromeを完全に閉じてから、開き直す
5. ページの「状態」の「使用中のGPU」が NVIDIA になっているか、AIが動いている最中にタスクマネージャーで NVIDIA 側が動いているかを確認する（ページ側の表示は目安なので、最終確認はタスクマネージャーで）

### モデルの選び方

ページのモデル一覧は、WebLLM本体が「今のバージョンで実際に動かせる」と宣言しているものを自動で表示します。【最速】〜【重い】は、必要なVRAMからの目安です。

| 目安 | モデル | 特徴 |
|---|---|---|
| まず試す | Qwen2.5 3B Instruct | 軽くて速い。指示にも比較的強い |
| 日本語重視 | Gemma 2 2B JPN | 日本語向けに調整された軽量モデル。操作の指示は弱いかもしれない |
| 余裕があれば | Qwen2.5 7B Instruct / Qwen3 8B | 精度は上がるが、返事は遅くなる |

- **DeepSeek-R1系などの「推論モデル」は、一覧から外してあります。** 返事の前に長く考える（思考を書く）ため、声かけや音声操作には遅すぎます
- **14B以上**は、2026年時点で、ブラウザ版（WebLLM）の公式対応リストにありません。32B以上は12GBのVRAMには収まりません
- ページの「速度テスト」で、短い説明文・軽量版・従来版（約3,400字）の3通りの返事時間と、1秒あたりの処理量（トークン）が分かります。**声のアシスタントとして自然に使えるのは3〜5秒以内**が目安です
- 「精度チェック」は、タイマー・アラーム・音楽・アプリ起動・ライト・音量・予定の追加・雑談（操作を出さないべき場面）の8項目を、アプリ本番と同じ文面でテストします。日本語に中国語が混ざっていないかも確認します。**モデルを切り替えるたびに実行して、成績のよいものを選んでください**
- パソコンにソフトを入れられるようになった場合は、Ollama などを使うと、より速く、Qwen2.5 14B（約9GB）も12GBのVRAMに収まります

### 精度チェックについて

声かけ文のサンプルも一緒に表示されるので、日本語の自然さは目で確認してください。

### 止まりにくくするために
- Windowsの「設定 > システム > 電源」で、スリープを「なし」にしておく
- Chromeの「設定 > パフォーマンス」で、メモリセーバーをオフにする
- 他の人がパソコンを使うときは、「サインアウト」ではなく「ユーザーの切り替え」を使ってもらう（サインアウトすると、ブラウザごと終了します）

## 「しつこい通知」の仕組み
- ⑥で設定した時間帯に自宅にいると、対象アプリを開くよう通知します
- 無視すると5分おきに再送し、対象アプリを開いてから3分以上離れると警告に切り替わります
- 警告は無視するたびに少しずつ強くなります（4段階）
- 「今日はもう休む」を選ぶと、その日はもう来ません。日付が変わると自動的にリセットされます

## 音声アシスタントの仕組み
- マイクの許可と「見守りを開始」（⑤）または「音声アシスタントを有効にする」（⑦）のどちらかでサービスが起動し、「ヘイ、デイリー」で会話が始まります
- 呼びかけていないのに勝手に反応する問題があったため、呼びかけの検出は厳しめ（閾値高め・連続検出4回）に調整済みです。それでも誤反応が多い場合は `voice/WakeDetector.kt` の `THRESHOLD` をさらに上げてください（0.8前後まで上げても実用上問題ありません）
- できること:
  - タイマー・アラーム: Android標準の時計アプリに直接セットします（自作の仕組みではないので確実です）。止める・消すよう頼まれた場合は、時計アプリの一覧を開くところまでで、そこから先はご自身で操作してください（標準の時計アプリには、個別の予定を外部アプリから取り消す仕組みが無いためです）
  - カレンダー: 端末のカレンダー（Googleカレンダーと同期）に直接、予定を追加できます。読み取りだけでなく書き込みもできます
  - メール: 「作成画面を開く」ところまでです。宛先・件名・本文を入れた状態でメールアプリ（Gmailなど）を開きますが、送信は必ずご自身で行います。受信箱を読む・検索することはできません（それにはGoogleの追加の認証設定が必要で、今回は含めていません）
  - Google Home: アプリを開くところまでです。「電気をつけて」のような個別の家電操作は、Googleが公式に許可したアプリ（スマートホーム連携の審査を受けたアプリ）でないとできない仕組みになっているため、このアプリからは直接操作できません
  - ライト・音量・画面の明るさ・電力モード・おやすみモード・マナーモード・アプリを開く・音楽の再生と操作・設定画面を開く
- 音楽をハンズフリーで再生するには「通知へのアクセス」の許可が必要です
- 画面の明るさ操作には「システム設定の変更」の許可、おやすみモード・マナーモード（無音）には「通知ポリシーへのアクセス」の許可がそれぞれ必要です
